P2PFlow v1.4.2 Hotfix - Verification Report
============================================

Purpose
-------
Fix the GitHub Actions release failure that remained after v1.4.1 and was reported as exit code 128.

Confirmed workflow defect
-------------------------
The v1.4.1 release workflow used:
- actions/checkout@v5
- fetch-depth: 0
- persist-credentials: false

and later executed:
- git fetch --tags --force

Because checkout credentials were intentionally not persisted, a later authenticated network git fetch can fail in a private repository with Git exit code 128. The release workflow no longer performs that redundant post-checkout fetch.

v1.4.2 changes
--------------
1. .github/workflows/release.yml
   - kept actions/checkout@v5
   - kept fetch-depth: 0
   - added fetch-tags: true
   - kept persist-credentials: false
   - removed redundant `git fetch --tags --force`
   - release metadata now uses the tags already fetched by checkout

2. Version
   - package.json: 1.4.2
   - package-lock.json root: 1.4.2
   - UI asset cache-busting: 1.4.2
   - unified install guide package filename: 1.4.2

3. Future version bump hardening
   - scripts/set-version.js now normalizes stale ?v=x.y.z asset query values
   - scripts/set-version.js now normalizes unified ZIP filenames in the install/update guides

4. v1.4.1 dependency repair retained
   - package.json override: postgres-interval = 1.2.0
   - package-lock resolves postgres-interval to 1.2.0
   - broken postgres-interval-1.3.0.tgz reference is not present

Environment limitation
----------------------
A full `npm ci --offline` dependency reinstall was attempted, but the sandbox did not have the `safer-buffer-2.1.2.tgz` package in its local npm cache. External npm registry download is unavailable from this execution environment. This is an environment/cache limitation, not the previous postgres-interval lock error.
