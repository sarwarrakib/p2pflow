P2PFlow v1.5.10 SMTP DIAGNOSTIC AUDIT
=====================================

ISSUE REPRODUCED FROM SOURCE
----------------------------
v1.5.9 classifyMailDeliveryError() classified any SMTP 550/551/552/553/554
response as recipient_rejected. SMTP servers also use these codes for sender policy,
MAIL FROM rejection, relay denial, and DATA policy rejection, so the UI could blame
the recipient even when the recipient was not the failing stage.

FIX
---
1. SMTP command/response flow now annotates failures with the protocol stage:
   CONNECT, EHLO, STARTTLS, AUTH, MAIL_FROM, RCPT_TO, DATA_COMMAND, DATA_BODY.
2. Error classifier now maps MAIL_FROM to sender_rejected and RCPT_TO to
   recipient_rejected.
3. Relay denial and generic SMTP policy rejection have separate diagnostics.
4. Health mail-test endpoint returns smtpStage and smtpCode together with provider
   response detail.
5. Settings UI displays stage/code/detail and allows an explicit test recipient.
6. If From Email is blank and SMTP Username is an email address, authenticated SMTP
   uses that username as the safe sender fallback before attempting a derived
   no-reply address.

SECURITY / DATA
---------------
- No SMTP password is returned to the UI.
- No login secret or OTP is exposed.
- Database schema unchanged.
- Existing encrypted database-backed state remains unchanged.
