P2PFlow v1.5.11 - Automatic Multi-Email Failover Audit
======================================================

Primary behavior
- Existing v1.5.10 Email Sending System remains the Primary route.
- Up to 3 ordered backup routes are supported.
- Backup routes are disabled by default after upgrade.

Coverage
- Login OTP
- Email recovery/security verification
- Order/assignment email
- Notification-center email
- Other application email using sendMailMessage()

Failover policy
- Primary is attempted first.
- Enabled backups are attempted in slot order.
- Provider/auth/quota/TLS/network/sender/relay/policy failures may advance to the next route.
- RCPT 4xx temporary deferral may advance to the next route.
- Permanent recipient rejection does NOT advance to another route.
- Ambiguous disconnect after SMTP DATA body with no explicit rejection code does NOT advance, preventing likely duplicate messages.

Secrets
- Each backup SMTP route has independent credentials.
- Backup SMTP password is stored inside the existing database-backed encrypted application state.
- Public Settings response exposes only smtpPasswordConfigured boolean, never the stored password.

Login safety
- Security Question / Owner Emergency Login starts only after the configured mail chain cannot deliver.
- Existing OTP-disabled PIN-only login remains unchanged.

Diagnostics
- Direct test per backup route.
- Full failover-chain test.
- Login OTP failover-chain test.
- Audit records failed route, provider/system, normalized failure code and successful route.

Validation
- npm test: PASS
- npm run build: PASS
- mail-failover-self-test: PASS
