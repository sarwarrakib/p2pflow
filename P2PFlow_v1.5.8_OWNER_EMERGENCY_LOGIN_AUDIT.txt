P2PFlow v1.5.8 Owner Emergency Login Audit
==========================================

Problem found in v1.5.7
-----------------------
The automatic Owner Emergency Login branch required the caught Login OTP error to
carry the internal `mailDeliveryFailure` object. If a hosting/provider path surfaced
the same mail failure without that metadata, the login handler could fall through to
the generic Email OTP error instead of returning the emergency challenge.

Fix in v1.5.8
-------------
1. Added normalizeLoginOtpDeliveryFailure(error).
2. Added loginOtpFailureFallback(user, req, error).
3. Login OTP send/resend failure now uses the normalized fallback path rather than
   requiring `error.mailDeliveryFailure` metadata.
4. Resend cooldown HTTP 429 is explicitly excluded from mail-outage classification.
5. Added explicit Owner emergency retry from login UI after a mail-delivery error.
6. Explicit retry verifies the configured mail route again. If delivery succeeds,
   normal OTP remains required; if it fails, fallback is issued.
7. Security Question remains preferred when configured.
8. Owner emergency still requires verified username/email + password first and then
   the existing 6-digit login secret.
9. Login email is never changed by this flow.
10. No Hosting Terminal command or local recovery-code file is used.
11. Challenge remains memory-only, 5 minutes, max 5 attempts, browser/network-bound.
12. Emergency login does not enroll a new Trusted Device.
